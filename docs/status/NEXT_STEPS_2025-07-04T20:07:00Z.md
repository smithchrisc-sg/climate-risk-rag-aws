# 📋 Current Text Extraction Flow Analysis

## Current Architecture
1. **TextExtractor Initiator** → Starts Textract jobs
2. **TextExtractor Processor** → Processes completed jobs, saves to `solve-global-kr-text-861276078413-us-east-1`
3. **Text Chunker** → Reads from text bucket, processes with smart chunker

## Current Text Extractor Output Structure
```
solve-global-kr-text-861276078413-us-east-1/
└── extracted_documents/{doc_hash}/
    ├── textract_response.json      # Complete Textract JSON
    ├── raw_text.txt               # Plain text in reading order
    ├── layout.csv                 # Layout structure (LAYOUT_ blocks)
    ├── key_values.csv             # Form key-value pairs
    ├── table_1.csv, table_2.csv  # Individual tables
    └── processing_metadata.json   # Processing statistics
```

## Smart Chunker Requirements
- Expects `textract_response.json` (complete Textract JSON) for structure analysis
- Needs `raw_text.txt` for text-only fallback
- Uses Textract blocks for intelligent structure detection

# 🔧 Detailed Structure Explanation

## Root Level: `{doc_id}/`
- **Rationale**: Consistent with your existing pattern across all buckets
- **Benefits**: Easy navigation, clear document isolation
- **Example**: `climate_report_001/`, `wb_procurement_guide/`

## Text File: `{doc_id}_full_text.txt`
- **Content**: Complete extracted text in reading order
- **Usage**: Primary input for text chunker and NLP processing
- **Format**: Plain UTF-8 text with natural line breaks

## Metadata Folder: `metadata/`
- **Purpose**: All structural and processing information
- **Benefits**: Clean separation of text vs. structure data

### Core Structure Files
1. **`textract_response.json`**
   - Complete Textract API response
   - Required by smart structured chunker
   - Contains all blocks, relationships, and geometry

2. **`document_structure.json`** (NEW)
   - Processed structure optimized for chunker
   - Pre-analyzed sections, headers, tables
   - Reduces processing time in chunker

3. **`layout_structure.csv`**
   - Layout blocks in tabular format
   - Easy analysis of document structure
   - Reading order and positioning data

### Specialized Data Folders
4. **`tables/`**
   - Individual table CSV files
   - `tables_summary.json` with table metadata
   - Preserves table structure for chunker

5. **`forms/`**
   - Key-value pairs from forms
   - Form field analysis
   - Structured data extraction

6. **`processing_info.json`**
   - Processing statistics and metadata
   - Quality metrics and confidence scores
   - File inventory and checksums
